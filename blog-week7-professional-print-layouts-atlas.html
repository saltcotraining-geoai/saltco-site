Week 6 gave us surfaces — rasters that let us ask where to build and how many people a district serves. Week 7 is the cartographic step: turning all that analysis into a proper, professional map product that can be printed and communicated clearly to a client or decision-maker.

A good map answers three questions at a glance: what, where, and when. That means choosing the right elements, controlling scale and extent, and making the layout readable on paper — not just on screen.

Why Week 7 Exists

Up to now we've focused on analysis. The final deliverable in applied GIS is almost always a map. This week we learn the standard workflow:

  1. Set up a clean Print Layout with a logical structure
  2. Prepare and lock the main map so it doesn't accidentally pan
  3. Add context with an inset map
  4. Include essential cartographic elements (grid, scale bar, north arrow, legend, title/subtitle)
  5. Add supporting info (attribute table, notes, data sources/credits)
  6. Use the Atlas to automate one page per district from a coverage layer
  7. Export at 300 DPI for printing/sharing

1) Recap — From Rasters to Map Production

We started with a quick recap of the raster work: reading pixels, reprojecting to UTM 36N, clipping, deriving slope/aspect, and using the Raster Calculator with Zonal Statistics context from the previous class. The goal now is to present those results clearly on a printed sheet.

2) Map Elements & Audience

Before touching the layout, we discussed what makes a map communicate:

  • Main map — the focus of the map (here, Red Sea State with our analysis layers)
  • Inset map — spatial context (showing Sudan/East Africa so the reader knows where Red Sea is)
  • Legend — translates symbols/colours to plain language
  • Scale bar — allows distance measurement
  • North arrow — orientation
  • Title/Subtitle — answers what, where, when
  • Grid — coordinate reference/measurements on the sheet
  • Notes/Credits/Data sources — attribution (e.g., OSM, data providers)
  • Attribute table (optional) — key figures for the area shown

3) Page Setup & Layout Structure with Guides

We created a new Print Layout and set the page size/properties for printing (A3 was used in context). The key trick was using Guides to divide the canvas into a clean structure:

  • Main map area (~80%) — largest section for the detailed map
  • Sidebar (~20%) — for inset, legend, north arrow, title/subtitle
  • Lower section — for attribute table, notes/credits and other supporting elements

Guides keep everything aligned and give a professional, balanced layout.

4) Building the Main Map

  1. Prepare layers — cleaned attribute tables (consistent naming), ensured all layers in the same CRS (UTM 36N)
  2. Add the map item — placed in the 80% main area, centered on Red Sea State (with context of Sudan visible)
  3. Style for clarity — roads/rivers/railway styled distinctly, boundaries clear, population/analysis layers styled readably
  4. Add a grid — enabled grid on the map, set interval/appearance (solid, very light grey) for a clean look
  5. Lock the map — critically important before setting up the inset and moving elements. Once locked, the map extent won't shift accidentally

5) Inset Map for Spatial Context

In the upper-right sidebar, we added a second Map item for the inset:

  • Zoomed out to show East Africa and the whole of Sudan
  • Styled to emphasize location — Sudan shown in a subdued grey, with Red Sea State highlighted in red
  • Linked for clarity — the inset shows where the detailed main map sits in the broader region

6) Cartographic Elements — Legend, Scale, North Arrow, Text

  • Title & Subtitle — clear, descriptive (answers what/where)
  • Legend — added, cleaned up item names (remove unnecessary layers), adjust columns/size for readability
  • Scale bar — added and formatted appropriately for the sheet
  • North arrow — simple, clean symbol placed in the sidebar
  • Notes & Credits — data sources (e.g., OSM), attribution, and any notes about the map
  • Attribute table — placed in the lower section with relevant fields, formatted to fit cleanly

7) Atlas — One Map Sheet Per District

The real power of the Print Layout is the Atlas. Instead of making a separate layout for each district, we automate it:

  1. Set coverage layer — use admin2_districts (or the district layer) as the Atlas coverage layer
  2. Configure page name — set the page name to a district attribute (so each exported page is clearly identified)
  3. Control the map extent — enable "Controlled by Atlas" on the main map so it zooms/pans to each district automatically
  4. Preview — use Atlas Preview to cycle through districts and check extents, labels, and layout
  5. Generate output — export as a multi-page PDF (300 DPI recommended) with one sheet per district

This is exactly what the client asked for: "one clean, printable A3 map sheet of each district — with grid and scale".

Common Hang-ups and Fixes

  1. Map pans when you don't want it to: Always lock the main map item once it's at the correct extent and scale. Do this before setting up Atlas/inset adjustments.
  2. Atlas zooms to the wrong place: Make sure the map item is set to "Controlled by Atlas" and using the correct coverage layer.
  3. Legend shows unwanted layers: In the legend item properties, uncheck "Auto update" and manually remove or reorder items, or filter to only visible layers as needed.
  4. Grid looks too heavy: Use a light grey, thin line style. Keep it readable but subtle so it doesn't overpower the map content.
  5. Attribute table doesn't fit: Resize and limit columns/fields to only what's necessary for the sheet. Use the lower section with guides for clean alignment.
  6. Export looks blurry: Export at 300 DPI (not screen resolution). Check page size matches what you intend to print.
  7. Elements misaligned: Use guides and alignment tools in the Print Layout. Keep consistent spacing between elements.
