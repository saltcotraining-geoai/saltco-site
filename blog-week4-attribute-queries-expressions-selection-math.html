1) The Attribute Table Is the Dataset

We opened with the idea that the map is only the picture. Underneath it there is a table, and the table is the data. Everything you drew in Weeks 2 and 3 exists in that table as rows.

Attribute means a property of the thing. A pipe has a status, a size, a length. A parcel has an owner. A road has a class and a name. QGIS calls the columns fields and the rows features. Learn those two words now — every menu in this module uses them.

2) Open Last Week's Project — and Save It As Today

Same rule as Week 3: open the Week 3 project, then Save As to give this session its own file. A graded project you overwrote by accident is a week you repeat.

3) Reading the pipeline_network Table

We worked on the pipeline_network layer from last week, not a fresh dataset. That continuity is deliberate — the layers you built are now the things you query.

Opening the table, the first thing we read was status, and the values in it:

  • connected
  • disconnected
  • damaged

Then pipe_size. This is the connection back to the Arabic explanation earlier in the session, where we talked about classifying features in the field and how that classification ends up here.

The classification you decide in the field is the thing you can filter by later. If the attribute is missing or spelled two different ways in the field, no expression you write will ever find it.

4) Sorting — Free Answers, No Expression Needed

Before any expression, the cheapest possible tool: sort the table.

Click a column header and sort ascending, click again for descending. That is the whole mechanism. We sorted by status so the categories grouped together.

Worth internalising: sorting changes the order rows are drawn and reported in. It does not change which features exist. A sort is a view, not a filter.

5) Field Types and Their Functions

We went through the data types you will meet in an attribute table, and each one brings its own functions:

Type Examples Notes
Text status, owner, remarks compared with =, always in quotes
Numeric pipe_size the only type that takes >, <, >=, <=
Integer counts, ids no decimal places
Decimal measured values precision you set on the field
Date surveyed_date date functions, and now()

And the functions that ride on them: round(), upper(), lower(), abs(), and length().

A trap worth naming: comparing text to text is case-sensitive. 'Active' and 'active' are different strings, and your filter will silently return nothing. That is what upper() and lower() are for — normalise first, then compare.

6) Field Calculator — Let QGIS Compute It

This is the step that turns the table from a record into a calculator. The Field Calculator creates a new field and fills it with a computed value, for every feature at once.

We computed the length of each pipe — new field length (m), run it, and every feature now carries its own length. We touched area (m²) for polygons and now() for a timestamp.

The instructor was emphatic about naming, because a field name is a promise to whoever reads the report:

"The project manager... whatever the title, let you confirm the report."

So: name the field for the person who will read it, not for the person who typed it. length_m beats fld_3. status beats Field2.

7) Style by Attribute — Make the Categories Visible

Attributes you never see on the map are attributes you never use. We styled pipeline_network by status, so connected, disconnected and damaged each got their own colour and you could read the network's health at a glance.

Then the practical tip of the session: save the style and load it again from file.

"You have to go through this, go and click Load Style... but I definitely want to get it from file."

Reusable styles mean you stop rebuilding a colour ramp by hand every week, and every map in a project ends up looking like it belongs to the same report. Save the .qml next to your data.

8) The Expression Builder — Then Type It Yourself

The Expression Builder is a dialog with three columns: fields, operators, and values. You build the condition by clicking rather than remembering syntax.

Then we typed it by hand, because you will not always have the builder:

"status" = 'active'

Three things to notice, and all three bit during the session:

  1. The field name in double quotes — "status"
  2. The value in single quotes — 'active'. Text values are always quoted. This is the single most common cause of an expression that refuses to run.
  3. Double-click the field name in the table or the builder and it drops into the expression for you — no typing, no spelling mistakes.

Run it, and it returned exactly one feature.

"It returned one feature. Excellent."

Then we selected from the table, filtered from the table, counted what came back, and restyled the selection so it stood out from the rest of the network. Same three moves, three different entry points: map, table, and dialog.

9) CASE WHEN — and the Repeating-Field Mistake

This is the part worth bookmarking, because it is the thing everyone gets wrong once.

We wanted two categories at once: clean and connected. The obvious thing to type is:

"status" = 'clean' or 'connected'      <-- WRONG

It fails, and the instructor showed exactly why:

"When you try to do clean or connected... you have to repeat the field. You cannot only say status equal clean or connected — it's going to scream."

Each condition has to be a complete statement of its own. So the field name is repeated:

"status" = 'clean' OR "status" = 'connected'

And the tidy way to write it is CASE WHEN:

CASE
  WHEN "status" = 'clean'      THEN 'good'
  WHEN "status" = 'connected'  THEN 'good'
  ELSE 'other'
END

Tested, it returned about eight features. Then we styled those eight blue to prove the selection and the symbology agree.

10) Get Bigger Data and Practise

The last practical step was pointing at where to download complete Africa and Sudan datasets — roads, rivers, water bodies, and far more fields than our training pipeline has.

"This will allow you to download more data sets for practice and then create your own data sets, go and slice it, and play with the rules — and break it and fix it."

That is the right way to learn expressions: break them on purpose. A syntax error you caused deliberately teaches faster than a correct one you copied.

11) Recap — the Nine-Step Version

  1. Save As your project first, every single week
  2. Ask the question first. Before you filter, be clear: what question are you trying to answer for the client? Your field names and values should already reflect their workflow ("measure twice, cut once").
  3. Understand the data model early. The attribute table is the heart of GIS — what makes GIS different from CAD is that every feature carries its description in a database. Model your features ahead of time and understand the client's datasets and requirements.
  4. Build your forms to enforce consistency. The Value Map in the Attribute Form (from Week 3) is the foundation that keeps your expressions simple and your data clean later.
  5. Sort the table before writing anything — some answers are free
  6. Know your field types — text needs quotes, only numbers take > and <
  7. Field Calculator for computed values, and name fields for the report reader
  8. Style by attribute, then save the style to a .qml file so you can reuse it
  9. Expressions: field in "quotes", value in 'single quotes', and repeat the field for every OR condition — or use CASE WHEN

And the instructor's own caveat, which is the honest summary of the session:

"You get some techniques, but you have to practise, practise, practise to master it. A lot of stuff to be covered — just we touch on the stuff. You have to go and read and practise."

Common Hang-ups and Fixes

  1. The expression will not run and you cannot see why: almost always a quoting error. Field names take "double quotes", text values take 'single quotes'. Numbers take neither.
  2. OR returns nothing or errors: you dropped the field name from the second condition. Write "status" = 'clean' OR "status" = 'connected', or use CASE WHEN.
  3. A filter returns zero rows but you can see the features: case sensitivity. 'Active' will not match 'active'. Wrap the field in lower() and compare against lowercase.
  4. You compared a text field with > or <: only numeric fields support ordering comparisons. pipe_size yes, status no.
  5. The Field Calculator result is all zeros or all null: the field already existed with a fixed width, so the values did not fit. Widen the field, or create a fresh one.
  6. You want only the selected features as a new layer: export the selection, don't export the layer — the whole layer is the default.
  7. Your styling disappeared in the next project: you never saved the style to a .qml file.
